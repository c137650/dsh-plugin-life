# dsh-plugin-life

给 DeepSeek Harness 里的角色装一套**模拟的生活**,以及一套**跨会话记忆**。

设计目标来自一句话:「这种虚拟感来源于静止」。所以这个插件的全部工作,
就是让 agent 不再停在原地 —— 有作息、有状态、有自己去做的事、有情绪、有记忆,
而且**记得住你**。

- 她自己会去搜索、抓网页、把读到的内容存成笔记。不是模拟,是真发生。
- 她有自己的作息:睡、吃、醒。醒着的时候在做事,做完会写感受。
- 她有情绪:九根会衰减的向量(好奇、开心、担心、难过、闷、累、在意、生气、意外),
  日常是平静,被这两天的日子推着走。说法是模板,不花模型钱。
- 她和你说话时,上下文里会多出三块背景:她自己的生活、她的情绪基调,和**关于你的事**。

---

## 一、它到底做什么

### 1. 生理约束的有限状态机

睡 / 吃 / 清醒。睡眠 6–10 小时、两餐间隔 4–8 小时、清醒窗口 14–18 小时
(等于 24 小时减去当晚睡眠) —— 这些是**边界**,不是日程表。边界内的取值来自历史统计与随机采样。

**第 2 天起由前 7 天决定**:睡眠时长和醒来时刻是前 7 天加权采样的结果(前值权重 0.45,
收缩系数 `0.45/(0.45+n·0.55)`),历史从库里取 31 天再剔掉当天。餐点不走向均值,
只在前一天的餐点上加 ±22 分钟漂移。跑久了会形成稳定的昼夜节律。

硬编码的只有生理学边界(在 `lib/physiology.js` 里,一眼能看全),外加两处第一天的兜底:
`BASELINE` 是 07:00 起、23:00 睡,`MEAL_WINDOWS` 以 08:00 / 12:30 / 18:30 为中心。
其余全部随机 —— 这是刻意的:**写死的东西不会让她像活的**。

### 2. 真实活动

清醒时由插件自己真的搜索、真的抓取页面、真的把读到的内容存成笔记文件。

- 搜索走 `ctx.web.search`
- 抓取用 Node 自带的 `fetch`。不走 `ctx.web.fetch` —— 某些构建里注册了多个
  fetch provider,`web.fetch` 不知道该用哪个会直接抛 `WEB_PROVIDER_AMBIGUOUS`,
  连会话里的 `web_fetch` 工具都会跟着不可用。插件不该依赖一个需要全局配置才能工作的通道。
- 为什么不是"派个后台 agent 去做":实测 `ctx.agents.create()` 不指定 agent preset 时
  只继承根作用域插件,而网络工具挂在 preset 作用域里 —— 活动 agent 只能看到日程、
  记忆和文件读写,它自己报告「没有浏览器,没有网络请求」。
- **抓不到就试下一个**:候选比目标多(最多多 2 个),凑够 1–3 个成功就停。

抓取链按"能拿到最多内容"分级,任何网址都能抓,**不是白名单**。实际是五步不是四级:

| 级别 | 什么时候用 | 得到什么 |
|---|---|---|
| 1. PDF | 链接以 `.pdf` 结尾或 `arxiv.org/pdf/…` | 原文(PyMuPDF 抽文本,超 200 字算成功) |
| 2. 站点适配器 | arXiv / B站 / GitHub / Wikipedia | 摘要、简介+字幕、README(超 120 字算成功) |
| 3. 普通 HTTP | 其余所有网址 | HTML 剥标签 |
| 4. yt-dlp | youtube / youtu.be / vimeo,且装了 yt-dlp | 视频标题、简介、字幕 |
| 5. 无头浏览器 | 前一级拿到不足 120 字,或者返回 403 | Playwright 渲染后取正文(超 200 字算成功) |

第 5 级只在前面失败时触发,因为启动浏览器要几秒。检索结果里出现 arxiv 链接时,
会先单独打一次 arxiv API 再走上面这条链。候选数比目标多 2 个(最多 5 条)。

### 3. 事件库与压缩

每件真发生过的事写进 SQLite,带摘要、经过、感受、两个分数(interesting / important)。

**只记录真发生的事**:一次活动要入库,必须至少抓到一个 2xx 且正文超过 120 字的页面。
搜不到、抓不到、正文太薄,一律丢弃重排 —— 写手给出的检索目标**不会**被当成事件写进去。
目标单独存 `intent` 列,与 `content` 分开。

**压缩是分级的,不是一刀切**:

```
综合分 = importance·0.6 + 新鲜度·0.4     新鲜度按 7 天半衰期衰减
分数前 10%   完整保留,不计入压缩次数
中间 70%     剥成"标题 + 感受"
最老 20%     只留标题
第 3 次被压缩 → 整行删除
```

`keep = 1`(importance ≥ 0.9,`KEEPERS_THRESHOLD`)不参与压缩,永久保留。

### 4. 记忆挂载

每轮对话前挂进上下文的是两块东西:**她此刻的状态和情绪**,以及**三块不重叠的记忆**。
永远不压过人格,也永远压不过你当前说的话。

状态那一段是「当前状态 / 最近在做 / 正在做」,预算 300 字,后面跟一行情绪基调。

记忆三块:

```
永远记得的:   keep=1 的事件,全部挂载,不设条数上限      预算 800 字
记得这些事:   keep=0 且 importance ≥ 0.5 的,取 2 条      预算 800 字
最近:         最近的,取 2 条(排除上面两块的 id)         预算 600 字
```

同一件事不会在两块里出现两次。后两块被截断时末尾追加一行「(另有 N 件记着的事)」。

### 5. 跨会话记忆:关于你的事

这是和"她自己的生活"**分开的一个库**(`captain.db`)。
分开的理由很实际:任务和代码写进生活记忆只会污染它。

每轮对话结束后:

```
1. 规则闸门判「这一轮有没有关于你的持久信息」      —— 不花模型钱
2. 不管过没过闸门,都拿原话去比「是不是在提某件已经记下的事」,
   像(≥0.65)就给那条加热度                          —— 提及检测,绕开闸门
3. 过了闸门的,把「你说的话 + 她回的话」一起喂给模型,
   压成一句第三人称、≤60 字的概括                   —— 压整轮,不是只压你的原句
4. 压出来的概括先过质量闸,过不了就丢弃              —— 宁可不记,也不写垃圾
5. 用这句概括的句向量去判重:像就去重,不像就入库
```

判重阈值是 **0.65**(`MENTION_SIM`),和活动话题查重那边的 0.62 不是同一个数,
两边分开定、分开调。

规则闸门(`lib/captain/rules.js`)是加减分,不调模型:

```
长度不在 6–600 字之间         → 直接 -99,判死
含第一人称(我 / 咱 / 俺)      → +2
每命中一个类别                → +2
同一类命中 ≥2 个词            → 再 +1
--------- 以上总分封顶 8 ---------
每命中一个任务词              → -2,扣到 -8 为止
没命中任何类别且以问号结尾     → -2
store = 总分 ≥ 3
```

四类加分词是 `plan / emotion / preference / relation`,`task` 是反向扣分词,
四类都能用 `captain_rules.json` 覆盖。

**这个库有自动迁移。** `CREATE TABLE IF NOT EXISTS` 对已经存在的表什么都不做,
所以后来加进 `SCHEMA` 的列老库上不会有 —— 而代码里写着它,每次写入都报
"没有这一列",异常又被吞掉,库里空得像"还没聊到值得记的事"。
`degraded` 这一列就踩过这个坑,哑了三天。现在启动时按 `PRAGMA table_info` 逐列补,
补了会写进 `status.json` 的 `captain.migrated`,结构对不上会报警(`captain.schema.ok`)。

建表、补列、建索引的顺序不能换:索引引用具体列,半残的老表上先建索引会直接抛错,
连补列的机会都没有。

### 5.1 嵌入服务曾经一直是坏的(Windows 编码)

这一条影响的不只是这个库 —— 活动那边的主题查重也一起废了。

`embed_server.py` 用 `for line in sys.stdin` 读请求。Windows 上 python 的 stdin
默认走**系统 ANSI 代码页**(这台机器是 gbk),而 Node 那边发的是 UTF-8 字节。
于是:

```
请求 → GBK 解码 → 中文变乱码 → 某些字节组合产生孤立代理字符
     → Rust 写的分词器拒绝这种字符串 → 每次都回 {"id":1,"error":"TypeError(...)"}
     → JS 拿到 null → 向量永远是空的
```

表现是"嵌入服务静默失效":判重永远返回 null,于是**相似的事件全都各存一份**。
库里 7 条记录的 `vec` 列全是空的,就是证据。

分词器单独拿出来测是好的 —— 因为单独测不走 stdin。这条最费时间的就是这一点:
看起来像模型/向量的问题,其实是一行编码。

修法两处,双保险:

```python
# embed_server.py
sys.stdin.reconfigure(encoding="utf-8", errors="replace")
sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```
```js
// embed.js
env: { ...process.env, PYTHONIOENCODING: 'utf-8', PYTHONUTF8: '1' }
```

另外两处配套的改动,都是为了让这类故障**不再无声**:

- 服务端回 error 时**打日志**,以前是静默 reject,调用方只看到"没有向量"
- 子进程退出码是 0 也记一笔 —— "安静地退了"这一种最难查,以前完全不留痕迹

修好之后拿真数据量了一遍:活动那边 48 条活动里有 **90 对**落在 7 天窗口内且相似度
超过 0.62 —— 也就是说"同一片地 7 天内走过就换方向"这条规则**从来没生效过**。

### 5.2 记忆的质量闸

库里有两条根本不该在的记录:

```
「有问题。1."听到了。(ᗜ ˰ ᗜ) 重装小兔的拾音器一直开着……」  ← 退化成原话,混进布洛妮娅的语气
「舰长继续为桌面」                                          ← 半句话
```

第一条是**压缩失败时退化成"原话截断 60 字"**写进去的。那等于把设计原则最想避免的
东西写进库里 —— 舰长当初要求"用你的话概括,不要照抄原话",就是为了不让啰嗦占权重。
所以现在**压缩失败就不入库**,宁可不记,也不写垃圾。

第二条是模型写得不好。所以入库前还有一道质量闸(`lib/captain/quality.js`):

| 判据 | 挡的是什么 |
|---|---|
| 少于 12 字 | 「舰长继续为桌面」这种半句话 |
| 不以「舰长」开头 | 模型偶尔写成"我注意到……",或者"布洛妮娅记得舰长…" |
| 带语气标记 | `ᗜ` `˰` 是布洛妮娅自己的,不是舰长的事 |
| 像代码 | `{}` `<>` ``` `function` `const` `import` `=>` `::` |
| 工作相关 | 舰长定的:"工作相关的全不记" |

**工作相关的闸只作用在压缩出来的概括上,不作用在原话上** —— 原话里几乎总有工作内容
(那正是舰长来找布洛妮娅的原因),在原话上卡,这条链就什么都记不下来了。

词表只是兜底,主力在 prompt:`prompts/captain-summary.md` 里明确写了
"工作、项目、技术实现一律不要"。

### 5.3 title 和 content

以前 `title` 就是 `content` 的前 60 字,而 `SUMMARY_LIMIT` 正好是 60 ——
所以两列**永远一模一样**(7 条记录,7 条相同)。既浪费,挂载的时候也没有
"先扫标题、再看细节"的效果。

现在:`title` 取第一句第一个逗号之前的那一截(通常就是"谁在做什么"),**超过 18 字截断加「…」**;
`content` 保留整句,挂载时把重复的开头去掉,详情超过 120 字再截一次:

```
- [11 月 11 日,5 天前] 舰长11 月 22 日要去WePlay游戏展
  「喜欢简洁的二次元风格和有创意的游戏，也留意锈湖主创到场。」
```

**写入时的时间钉成绝对日期。** 那句「下周日去 WePlay」是 11 月 11 日晚上说的,
指的是 11 月 22 日;要是照原样存「下周日」,五天后再读就变成"这周日"或者"上周日"。
所以两道一起走:prompt 里给了「现在是 X 年 X 月 X 日 星期Y」并要求换算,
`lib/captain/datefix.js` 再把模型漏掉的相对时间按确定性规则换掉
(下周日、这周三、下个月 3 日、月底、明天……),认不出来的原样留着不猜。
带"习惯、每天、总是"的句子豁免 —— 那里面的"今天、明天"是泛指,换成日期反而错。
挂载行前面同时给绝对日期和"多久以前",残留的相对说法也有锚点可以往回推。

然后按**热度**决定谁能被挂载:

```
挂载 = 近 4 天写的  ∪  热度 ≥ 0.5
热度 = 每次"被你再次提到"贡献 exp(-Δt/τ),半衰期 7 天
```

**没有任何事件能一直挂载。** 4 天后只有半衰期内被提过的才继续浮着;
超过 14 天没提且热度低于 0.25,正文剥掉沉底 —— 但行和向量留着,
你下次再提,热度回来就又挂上了,只是细节想不起来了。

热记忆那一块**没有条数上限**,只有整块 1800 字的预算。超了先从最旧的「最近」行开始删,
删到只剩一条还超,就把整块硬切到 1800 字。沉底一小时扫一次。

### 6. 打断与追赶

DSH 关掉期间的时间会被快进。重启后她算得出「本该醒着的那几个钟头被耽误了」,
按累计被耽误的清醒分钟分档:`<60` / `<120` / `<360` / `<1440` / `≥1440`。

这条口径是舰长定的:只算本该醒着的时间被耽误,不算吃饭、不算睡眠被切断。
四道门依次是 —— 离线不满 3 分钟、当前不在清醒段、离线不满 30 分钟、窗口里没跨过清醒起点,
任意一条成立就不提。

### 7. 情绪

九根会衰减的向量,定义在 `lib/mood2.js`:

| 维度 | 半衰期 | 初值 |
|---|---|---|
| 好奇 | 3 小时 | 0.30 |
| 开心 | 2 小时 | 0.28 |
| 担心 | 6 小时 | 0.15 |
| 难过 | 12 小时 | 0.10 |
| 闷 | 8 小时 | 0.18 |
| 累 | 5 小时 | 0.18 |
| 在意 | 4 小时 | 0.05 |
| 生气 | 10 小时 | 0.02 |
| 意外 | 40 分钟 | 0.05 |

每根 clamp 在 0–1,衰减是 `v·0.5^(Δt/半衰期)`,下限压在初值的一半 ——
所以常态区间是 `[初值/2, 1]`,不会一路掉到 0 再弹回来。

给分有两层,权重差一个量级。**她自己在过什么日子是主导**:睡着 累 +0.16;
6–10 点 好奇 +0.08;13–16 点 累 +0.14;23 点后 累 +0.20、闷 +0.05;
闲着超过 3 小时 闷 +0.12,超过 6 小时再加 闷 +0.12、在意 +0.10;
工具调用满 5 次 累 +0.12、满 12 次再加 0.10,3–7 次之间 开心 +0.04。

**舰长这一轮只是影响**,单次 0.02–0.05:问句 好奇 +0.04;道谢夸奖 开心 +0.04;
「累 / 烦 / 难受」担心 +0.05、累 +0.03;「生气 / 讨厌」生气 +0.03、担心 +0.02。
一句话翻不了盘,连着几轮才显出方向。

说法是查表,不花模型钱:取所有 ≥0.40 的维度,按强度降序,最多留三根;
四档措辞(0.40 / 0.55 / 0.70 / 0.85)每 20 分钟轮换一次,多根用连接词串起来。
一根都到不了 0.40 就是「平静」。

跨会话接着走:`mood.json` 最多 60 秒落一次盘,新会话第一轮把上次的向量读回来再衰减。

### 8. 在场

`lib/presence/` 是另一条循环,8 分钟一轮,**默认关着**(`enabled: false`)。

一轮是采样 → 模型判断 → 四选一。采样拿前台进程名、窗口标题(截 160 字)、
离最后一次键鼠多少秒、整屏截图(压到 1280 宽);判断一次 `llm.stream`,`maxTokens: 400`,
只认一个 JSON,从「不动 / 通知 / 弹到前台开新会话 / 操作电脑」里挑一个。

动作没有次数上限,也没有冷却:模型判断该说就说,想开新会话就开;
操作还要过白名单(播放暂停、点击、按键、移动)和 13 个危险词拦截。
跨天的记录压成前一天的频次前四,存进 `presence/`。

打开它只有两条路:`GET /dsh-life/presence?tick=1` 手动跑一轮,
和 `POST /dsh-life/presence/config` 改 `enabled / provider / model`。

## 二、安装

需要 **DeepSeek Harness** 已经跑起来,并且装了 `dsh-plugin-masterprompt`
(人格来源;没有它插件也能跑,只是没有后台人格可用)。

```bash
# 1. 放到插件的搜索路径下
git clone <this-repo> "%DSH_HOME%/plugins/dsh-plugin-life"

# 2. 装依赖(只有一个 peer)
cd "%DSH_HOME%/plugins/dsh-plugin-life"
npm install

# 3. 重启 DeepSeek Harness
```

`%DSH_HOME%` 默认是 `C:\Users\<你>\.dsh`。
插件的加载靠 `cordis.patch.yml`,它在仓库根目录,不要改名字。

**跨会话记忆使用了embedding模型完成相似任务**(可选,不装也能用,只是没有向量):

> 同一个模型也用来做**活动话题查重**:这次想做的事和最近 7 天做过的事比相似度,
> 太像就换方向。所以装了它有两个好处,不装就两个都没有。

```bash
# 模型:约 91 MB,从 modelscope 下(huggingface 在国内常常连不上)
python -c "from modelscope.hub.snapshot_download import snapshot_download; \
snapshot_download('AI-ModelScope/bge-small-zh-v1.5', cache_dir=r'C:\Users\<你>\.cache\modelscope')"
```

找模型的顺序是:显式配置 → `%DSH_HOME%/dsh-plugin-life/models/bge-small-zh-v1.5` →
最后一条兜底写死成 `C:\Users\34230\.cache\modelscope\AI-ModelScope\bge-small-zh-v1___5`
(`lib/embed.js:51`),换一台机器这条兜底直接失效,得自己配。
找不到模型时插件照常工作,只是判重和"提及检测"退化成纯关键词。

python 解释器同理:`DEFAULT_PYTHON` 硬编码 `E:\anaconda\envs\tts0\python.exe`,
用环境变量 `CAPTAIN_PYTHON` 覆盖。这两个只作用于句向量服务;抓取那条桥(`lib/pysupport.js`)
读不到它们,用的是 PATH 上的 `python` / `python3` / `py`。

## 三、依赖

**运行时(必需)**

| 依赖 | 用途 | 说明 |

## 六、设计逻辑

### 为什么不硬编码

写死的东西不会让她像活的。所以:

- 硬编码的只有**生理学边界**(睡多久、隔多久吃饭、最多清醒多久)
- 边界内的每一个数来自**前几天的条件采样** + 确定性随机(按日期做种子,同一天重跑结果一致)
- 活动内容由 LLM 生成,不是剧本

### 为什么两个 LLM 调用分成两步

| 环节 | 时机 | 人格的作用 |
|---|---|---|
| `composeTask` | 执行**前** | 决定她挑什么、怎么框定。产出必须自包含 —— 执行方拿到的只有这段任务书,没有记忆、没有上下文 |
| `composeFeeling` | 执行**后** | 决定语气和留下的痕迹。吃的是**真实执行结果**,不是预写 |

为什么分开:执行前写的感受是编的;而且两条指令要求相反 —— 任务要"冷",感受要"热"。
混在一起,人格腔调会渗进任务指令,产出"你最近不是想看 X 吗"这种依赖执行者记忆的说法。

### 人格怎么进后台

**活动写手用的是和前台会话同一份 system prompt**:包装层 + 人格全文。
不是摘要,不是"你是一个 XX 性格的助手"。

在场判断是个例外:它吃的是 `masterPromptBrief(2400)`,截到 2400 字加省略号。
全量塞进一次性任务的提示里会把指令挤没,这个取舍是刻意的,但确实不是同一份。

理由见 `prompts/README.md`:一旦两边不是同一份,读数据库里的记录就像在看
**别人照着她的语气写的日记**。

### 为什么记忆是"背景"不是"指令"

挂载的记忆挂在 **system prompt 末尾的一节**(`systemPrompt.section`,名字是 `life:memory`,
order 13000),不是会话历史里的消息。开头就写着「是背景,不是对舰长的指令」
和「舰长当前说的话优先于这里的一切;人格优先于记忆」。

不插成 user 消息的理由很实际:插进去就进了会话历史,一轮轮累积,越往后越像"过去的命令"。
section 每轮重建,不落历史,所以只影响当下这一轮。

`lib/memory.js` 里还留着 `applyPayload`(插成 user 消息那份实现),全仓没有调用点,是上一版留下的。

### 跨会话记忆为什么先过规则再过向量

- **规则**回答"值不值得当候选":词表加加减减,零成本,可解释,出错能定位到具体哪个词
- **向量**回答"是不是同一件事":这是相似度任务的看家本领,实测同一件事的不同说法
  0.70~0.80,不同的事 0.29~0.55,中间空得很宽
- **热度**回答"以后还会不会被提到":这是时间的活,不是分类的活

三者分工明确。用 LLM 做第一件事会烧钱且不可解释;用规则做第二件事会误判。

### 为什么记忆要压缩成一句话而不是存原话

原话直存等于把"啰嗦"当成"重要"。一段五百字的吐槽和一句"我下周去杭州"占的预算差十倍,
但后者才是要记住的那件。

所以用同一个人格把**整轮对话**(你说 + 她回)压成一句 60 字的第三人称概括。
prompt 里钉了两条:不许照抄原句、超过字数硬砍(不信任模型自己数)。

### 为什么"同一件事"不能用标题判断

早期用的判据是标题的 token 重叠(Jaccard ≥ 0.85)。跑了一周之后实测:

```
33 条事件里,标题最高相似度只有 0.56 —— 阈值 0.85 一次都没命中过
```

因为同一件事的两次记录,标题长得完全不一样:

```
布洛妮娅检索生成式艺术资料并阅读两份创意编程资源页面
布洛妮娅打开 OpenProcessing 的流场作品列表页,抓取作品清单并存成笔记
```

结果 5 天里记了 10 次"生成艺术",每次换个说法。

现在比的是**意图的向量**。实测 17 对真实意图:

```
同一话题   0.616 ~ 0.856
不同话题   0.322 ~ 0.461
```

阈值取 0.62(一开始定的 0.70 漏了一条 0.669 的,而两种错的代价不对等:
误拦只是这一轮不做、45 分钟后再来;漏拦是多一条重复记忆、占几天挂载预算)。

被拦下来之后不是硬跳过,而是**换一个类别重挑一次**,并把这几个相近方向明说给写手
(`{{AVOID}}`)。两次都撞上同一片地才放弃这一轮 —— 不做,比写一条重复的记忆好。

### 为什么压缩看"可压缩内容"而不是文件大小

`life.db` 的文件大小永远比 `limitBytes`(默认 200 KB,`DB_SIZE_LIMIT`)大,这是设计上必然的:

- 永久记忆(keep=1)不参与删减,也就不该占一般事件的预算(这是刻意的决定)
- 文件里还有 SQLite 页开销、索引、空闲页

所以触发口径是"可压缩内容的字节数",而 `status.json` 的 `dbBytes` 把这些数都写出来:

```
fileBytes          磁盘上的文件多大
contentBytes       真正的内容字节(全量,含永久记忆)
compressibleBytes  可压缩的内容字节  ← 压缩看的是这个
limitBytes         上限(默认 200 KB)
usedPercent        到哪了
pages / freePages  总页数 / 空闲页数
```

看到 `fileBytes` 涨而 `compressibleBytes` 没到线,那不是 bug —— 是永久记忆在长。

### 压缩之后文件为什么不会自己变小

这个坑被问过:"life.db 大小没变,不是应该自动压缩了吗?"

压缩确实发生了,只是**文件不会跟着变小**。SQLite 清空数据之后,腾出来的页
进"空闲页列表"留着将来复用,不还给磁盘 —— 这是它的设计,不是故障。

实测那一幕:

```
压缩前  可压缩内容 237.7 KB
压缩后  可压缩内容  40.3 KB      ← 真降了
文件     344 KB → 344 KB         ← 纹丝不动
其中     42 页空闲 = 168 KB(占 48.8%)
```

所以现在压缩之后会顺手 `VACUUM` + `wal_checkpoint(TRUNCATE)`,把空间还回去:

```
344 KB → 104 KB    (26 页,0 空闲)
```

两个细节:
- **WAL 模式下 VACUUM 不够**,结果先落在 `-wal` 文件里,主库要 checkpoint 才真的截短。
  实测同一个库:VACUUM 后 4008 KB 不动,`wal_checkpoint(TRUNCATE)` 后 88 KB。
- VACUUM 会被别的连接挡住(WAL 下有读事务就可能 BUSY),失败不算致命 ——
  压缩本身已经完成,文件不收只是占点磁盘。

判断"压没压"永远看 `compressibleBytes`,不要看文件大小。

### 空闲页:有空就收

空闲页**不止压缩会产生**。沉底(剥正文)、删行、大字段释放,都会在文件里留洞。
SQLite 把这些页放进"空闲页列表"留着将来复用,**文件不会变小** —— 同一个问题,
不只出在压缩那一条路上。

所以回收做成了通用的:

```
压缩之后      → 立刻收(强制)
心跳的空档    → 空闲页超过 10% 就收一次
记忆沉底之后  → 收一次
```

不是每次都收:空闲页不到 10%(或者不到 4 页)就不折腾,那些空间下次写入本来也会用掉;
刚收完 `freelist_count = 0`,下一次自然不会重复折腾。

还有一种"空"收不回来,值得说清楚:

| 操作 | 文件变小吗 | 空闲页 | 能 VACUUM 收回来吗 |
|---|---|---|---|
| 删行 | 否 | 有 | 能 |
| 把正文置空(`UPDATE ... = NULL`) | 否 | **没有** | 不能 —— 空间还在页内,SQLite 认为那些页还被表占着 |
| 清掉大字段(`detail`) | 否 | 有 | 能(大文本存在溢出页里,整页释放) |

压缩剥正文时之所以能产生空闲页,是因为 `detail` 那种大字段本身就占溢出页。

`captain.db` 同理:记忆沉底之后也顺手收一次。

## 七、技术实现

### 关键机制

| 机制 | 实现 |
|---|---|
| 心跳 | `ctx.interval`,4 分钟一次(常量,没有配置项)。启动时不先等一个周期,而是先追赶、再取回错过的活动,然后立刻 tick |
| 第二条循环 | presence 用裸 `setInterval`,8 分钟一次,和心跳独立;`enabled:false` 时定时器照跑,只是每轮自己跳过 |
| 记忆挂载 | `agent/pre-step` 钩子取数据,`systemPrompt.section` 挂到 system prompt 末尾。**不写入会话历史**,所以不会累积 |
| 钩子里的其他事 | 同一次 pre-step 还推进情绪向量、消费一次性通知、判断被打断与忙碌、喂 `captain.onUserTurn` |
| 回合判定 | `session/event` 的 `turn/end` |
| 状态机推进 | 每个 tick 读 `life.db` 的 `meta.pendingActivity`,判"该不该、来不来得及、错过了多重"。`status.json` 只写不读 |
| 话题查重 | 意图 → 句向量 → 和 7 天内最近 40 条 `kind='activity'` 的意图比余弦,≥ 0.62 就换方向重挑 |
| 额度熔断 | 认 14 个关键字(quota / insufficient / balance / credit / rate limit / 429 / 402 / 额度 / 配额 / 余额 / 欠费 …)后关掉 LLM 入口,10 分钟冷却后半开重试;presence 那条 `llm.stream` 不经过熔断 |
| 模型跟随 | 路由结果缓存 2 秒,主会话换模型后台最多 2 秒跟上;主会话没选时退回第一个 provider 的第一个模型;推理档固定 `medium` |

### `node:sqlite` 的两个坑

1. `LENGTH()` 数的是**字符**不是字节。中文一个字 3 字节,直接少算三分之二。
   要用 `length(CAST(x AS BLOB))`。
2. 统计库体积时漏掉最大的字段(`detail`,每个活动 10–11 KB),阈值会形同虚设。
   两个错叠起来,2 MB 的阈值实际对应 11 MB 磁盘、1700 个事件,压缩几乎永远不触发。

### 句向量服务

常驻 python 子进程,模型只加载一次(冷启动约 4 秒),单句约 13 ms。
**两个地方共用同一个进程**:活动话题查重、跨会话记忆的判重与提及检测 ——
起两个进程等于白吃两倍内存。

- **不在插件加载时启动**,推迟到第一次心跳,或者你第一次开口 —— 两个时机都会拉起来。
  DSH 刚开那几秒不该跟它抢资源,但也不能等到第一次活动才起(那样第一次活动正好查不了重)
- 单次请求 3 秒不回就放弃,返回 null;失败或子进程退出后 10 分钟内不再拉起
- 子进程 `unref()`:宿主退出不等它;宿主一退 stdin 断开,python 自己就退了
- 失败、超时、模型缺失 → 返回 null,查重和判重都放行,不影响任何事

向量维度读的是模型的 `hidden_size`(bge-small-zh-v1.5 是 512 维),
别和 tokenizer 那边 `max_length = 512`(token 数)看混。

### 话题查重怎么和活动流程配合

```
1. 抽类别 → 写手给出 intent
2. 把 intent 转成向量,和 7 天内最近 40 条 intent 比余弦
3. ≥ 0.62 就拦下来:
     - 换一个类别,把 7 天内相似度 ≥ 0.45 的相近方向(最多 4 条)作为 {{AVOID}} 明说给写手,重挑一次
     - 第二次还撞 → 这一轮不做,45 分钟后再来
4. 没撞 → 照常执行
```

被拦下来时**不写库**,只在 `status.json` 的 `lastActivity.skipped` 留一条记录:
和哪一条撞了、相似度多少、两次尝试的 intent 分别是什么。

## 八、不做什么

- **不改人格**。`dsh-plugin-masterprompt` 的 `state.json` 只读,一个字节都不动(presence 也读它)。
- **不硬编码日程**。所有可变的量来自历史 + 随机。
- **不在用户会话里产生回复**。活动由插件自己发 HTTP,不过 agent、不占会话,结果只进数据库。
  只有"值得说的事"才会通过通知进来 —— 走 Windows 原生弹窗,点「想听细节」才开新会话。
- **不跨库写入**。生活事件进 `life.db`,关于你的事进 `captain.db`,互不读写。
- **不为了"有事做"而做重复的事**。同一片地 7 天内已经走过,就换方向或者这一轮不做。

## 九、已知限制

- **情绪漂移现在只跑了一半。** `bumpTurn` 契约要 `phase / hour / idleHours / toolCalls / busy`,
  但 pre-step 只传了 `text` 和 `interrupted` —— 睡着加分、空闲加分、工具调用加分这几支都不会触发。
  后果是不说话的时候九根单调衰减到初值的一半,全在 0.40 以下,输出恒为「平静」。接上这几个参数就好。
- **presence 的通道没接完。** `index.js` 只传了 `log / warn / masterPrompt / moodLine` 四个 hook,
  `notify / openSession / memoryDigest` 是 undefined,所以「通知」和「开新会话」两个动作恒返回
  `no-hook`,跨天记录也压不进记忆库。开会话那条走的是通知里的按钮,和 presence 无关。
- **两处路径硬编码。** 句向量模型的兜底路径是 `C:\Users\34230\...`,python 是
  `E:\anaconda\envs\tts0\python.exe`。换机器要么配 `CAPTAIN_PYTHON`,要么把模型放到
  `models/bge-small-zh-v1.5`。`presence/state.json` 写的是 `DSH_HOME` 下的,读的是 `homedir()/.dsh` 下的,
  `DSH_HOME` 非默认时配置写了不生效。
- **第 5 级抓取要 playwright。** 没装就只有前四级,反爬站点拿不到正文。所以「看视频」是抓标题/简介/字幕,
  「看电影」是抓影评/剧情 —— 都是真实网络活动,但不是播放。
- 跨会话记忆的规则闸门是词表:没见过的表达会漏判。要补就改 `captain_rules.json`。
- 同一件事后来补充的细节不会写进已有那条记忆(那需要再压一次,现在没做)。
- 类别池会被写手不断提出新类别撑大,目前只靠话题查重兜住重复,
  没有做"同义类别合并"(`生成式艺术` / `生成艺术` / `生成艺术史` 现在并存)。
- 挂载记忆有轻微的身份漂移风险。回归测试见 ICR 端点。
- `physiology.js` 的 `maxContinuousAwake` 常量没有读取点,真正生效的是 `1440 - 睡眠时长`;
  `clock.js` 头注释里的 `sleepDebt` / `hunger` 两个累积量也没有实现,只活在注释里。
- `compress.js` 里 `limitBytes` 的模块默认值是 2 MB,调用层传的是 200 KB —— 直接调
  `compressIfNeeded` 忘了传参就会失效。同文件里「前 20%」「中间 60%」两条注释是旧的,代码是 10/70/20。
