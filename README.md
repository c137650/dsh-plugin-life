# dsh-plugin-life

给 DeepSeek Harness 里的角色装一套**模拟的生活**,以及一套**跨会话记忆**。

设计目标来自一句话:「这种虚拟感来源于静止」。所以这个插件的全部工作,
就是让 agent 不再停在原地 —— 有作息、有状态、有自己去做的事、有记忆、
会因为被打断而生气,而且**记得住你**。

- 她自己会去搜索、抓网页、把读到的内容存成笔记。不是模拟,是真发生。
- 她有自己的作息:睡、吃、醒。醒着的时候在做事,做完会写感受。
- 她和你说话时,上下文里会多出两段背景:她自己的生活,和**关于你的事**。

---

## 一、它到底做什么

### 1. 生理约束的有限状态机

睡 / 吃 / 清醒。睡眠 6–10 小时、两餐间隔 4–11 小时、连续清醒不超过 16 小时 ——
这些是**边界**,不是日程表。边界内的取值来自历史统计与随机采样。

**第 2 天起由前 n 天决定**:睡眠时长、醒来时刻、餐点都是前几天的条件采样结果。
跑久了会形成稳定的昼夜节律。

硬编码的只有生理学边界(在 `lib/physiology.js` 里,一眼能看全)。
其余全部随机 —— 这是刻意的:**写死的东西不会让她像活的**。

### 2. 真实活动

清醒时由插件自己真的搜索、真的抓取页面、真的把读到的内容存成笔记文件。

- 搜索走 `ctx.web.search`
- 抓取用 Node 自带的 `fetch`。不走 `ctx.web.fetch` —— 某些构建里注册了多个
  fetch provider,`web.fetch` 不知道该用哪个会直接抛 `WEB_PROVIDER_AMBIGUOUS`,
  连会话里的 `web_fetch` 工具都会跟着不可用。插件不该依赖一个需要全局配置才能工作的通道。
- 为什么不是"派个后台 agent 去做":实测 `ctx.agents.create()` 不指定 agent preset 时
  只继承根作用域插件,而网络工具挂在 preset 作用域里 —— 活动 agent 只能看到日程、
  记忆和文件读写,它自己报告「没有浏览器,没有网络请求」。
- **抓不到就试下一个**:候选比目标多(最多多 2 个),凑够 1–3 个成功就停。

抓取链按"能拿到最多内容"分级,任何网址都能抓,**不是白名单**:

| 级别 | 什么时候用 | 得到什么 |
|---|---|---|
| 1. PDF | 链接是 `.pdf` 或 `arxiv.org/pdf/…` | 论文原文(PyMuPDF 抽文本) |
| 2. 站点接口 | arXiv / B站 / GitHub / Wikipedia | 摘要、简介+字幕、README |
| 3. 普通 HTTP | 其余所有网址 | HTML 剥标签 |
| 4. 无头浏览器 | 前一级内容太薄或返回 403 | Playwright 渲染后取正文 |

第 4 级只在前面失败时触发,因为启动浏览器要几秒。

### 3. 事件库与压缩

每件真发生过的事写进 SQLite,带摘要、经过、感受、两个分数(interesting / important)。

**只记录真发生的事**:一次活动要入库,必须至少抓到一个 2xx 且正文非空的页面。
搜不到、抓不到、正文为空,一律丢弃重排 —— 写手给出的检索目标**不会**被当成事件写进去。
目标单独存 `intent` 列,与 `content` 分开。

**压缩是分级的,不是一刀切**:

```
综合分 = importance·0.6 + 新鲜度·0.4     新鲜度按 7 天半衰期衰减
分数前 10%   完整保留,不计入压缩次数
中间 70%     剥成"标题 + 感受"
最老 20%     只留标题
第 3 次被压缩 → 整行删除
```

`keep = 1`(importance ≥ 0.75 的重要事件)不参与压缩,永久保留。

### 4. 记忆挂载

每轮对话前把记忆挂进上下文,**但永远不压过人格,也永远压不过你当前说的话**。

挂载是有优先级的,而且是**三块不重叠**的:

```
永远记得的:   keep=1 的事件,全部挂载,不设条数上限
记得这些事:   importance ≥ 0.5 的,取 2 条
最近:         最近的,取 2 条
```

同一件事不会在两块里出现两次。

### 5. 跨会话记忆:关于你的事

这是和"她自己的生活"**分开的一个库**(`captain.db`)。
分开的理由很实际:任务和代码写进生活记忆只会污染它。

每轮对话结束后:

```
1. 规则闸门判「这一轮有没有关于你的持久信息」      —— 不花模型钱
2. 过了闸门的,把「你说的话 + 她回的话」一起喂给模型,
   压成一句第三人称、≤60 字的概括              —— 压整轮,不是只压你的原句
3. 用这句话的句向量去判重:像就去重,不像就入库
```

**这个库有自动迁移。** `CREATE TABLE IF NOT EXISTS` 对已经存在的表什么都不做,
所以后来加进 `SCHEMA` 的列老库上不会有 —— 而代码里写着它,每次写入都报
"没有这一列",异常又被吞掉,库里空得像"还没聊到值得记的事"。
`degraded` 这一列就踩过这个坑,哑了三天。现在启动时按 `PRAGMA table_info` 逐列补,
补了会写进 `status.json` 的 `captain.migrated`,结构对不上会报警(`captain.schema.ok`)。

建表、补列、建索引的顺序不能换:索引引用具体列,半残的老表上先建索引会直接抛错,
连补列的机会都没有。

### 6.1 嵌入服务曾经一直是坏的(Windows 编码)

这一条影响的不只是这个库 —— 活动那边的主题查重也一起废了。

`embed_server.py` 用 `for line in sys.stdin` 读请求。Windows 上 python 的 stdin
默认走**系统 ANSI 代码页**(这台机器是 gbk),而 Node 那边发的是 UTF-8 字节。
于是:

```
请求 → GBK 解码 → 中文变乱码 → 某些字节组合产生孤立代理字符
     → Rust 写的分词器拒绝这种字符串 → 每次都回 {"id":1,"error":"TypeError(...)"}
     → JS 拿到 null → 向量永远是空的
```

表现是"嵌入服务静默失效":判重永远返回 null,于是**相似的事件全都各存一份**。
库里 7 条记录的 `vec` 列全是空的,就是证据。

分词器单独拿出来测是好的 —— 因为单独测不走 stdin。这条最费时间的就是这一点:
看起来像模型/向量的问题,其实是一行编码。

修法两处,双保险:

```python
# embed_server.py
sys.stdin.reconfigure(encoding="utf-8", errors="replace")
sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```
```js
// embed.js
env: { ...process.env, PYTHONIOENCODING: 'utf-8', PYTHONUTF8: '1' }
```

另外两处配套的改动,都是为了让这类故障**不再无声**:

- 服务端回 error 时**打日志**,以前是静默 reject,调用方只看到"没有向量"
- 子进程退出码是 0 也记一笔 —— "安静地退了"这一种最难查,以前完全不留痕迹

修好之后拿真数据量了一遍:活动那边 48 条活动里有 **90 对**落在 7 天窗口内且相似度
超过 0.62 —— 也就是说"同一片地 7 天内走过就换方向"这条规则**从来没生效过**。

### 6.2 记忆的质量闸

库里有两条根本不该在的记录:

```
「有问题。1."听到了。(ᗜ ˰ ᗜ) 重装小兔的拾音器一直开着……」  ← 退化成原话,混进布洛妮娅的语气
「舰长继续为桌面」                                          ← 半句话
```

第一条是**压缩失败时退化成"原话截断 60 字"**写进去的。那等于把设计原则最想避免的
东西写进库里 —— 舰长当初要求"用你的话概括,不要照抄原话",就是为了不让啰嗦占权重。
所以现在**压缩失败就不入库**,宁可不记,也不写垃圾。

第二条是模型写得不好。所以入库前还有一道质量闸(`lib/captain/quality.js`):

| 判据 | 挡的是什么 |
|---|---|
| 太短 | 「舰长继续为桌面」这种半句话 |
| 不是第三人称 | 模型偶尔写成"我注意到……" |
| 带语气标记 | 「(ᗜ ˰ ᗜ)」是布洛妮娅自己的,不是舰长的事 |
| 像代码 | 混进来的技术片段 |
| 工作相关 | 舰长定的:"工作相关的全不记" |

**工作相关的闸只作用在压缩出来的概括上,不作用在原话上** —— 原话里几乎总有工作内容
(那正是舰长来找布洛妮娅的原因),在原话上卡,这条链就什么都记不下来了。

词表只是兜底,主力在 prompt:`prompts/captain-summary.md` 里明确写了
"工作、项目、技术实现一律不要"。

### 6.3 title 和 content

以前 `title` 就是 `content` 的前 60 字,而 `SUMMARY_LIMIT` 正好是 60 ——
所以两列**永远一模一样**(7 条记录,7 条相同)。既浪费,挂载的时候也没有
"先扫标题、再看细节"的效果。

现在:`title` 取第一句第一个逗号之前的那一截(通常就是"谁在做什么"),
`content` 保留整句,挂载时把重复的开头去掉:

```
- [3 天前] 舰长习惯使用语音输入
  「停顿稍长时容易重复说同一句话。」
```

然后按**热度**决定谁能被挂载:

```
挂载 = 近 7 天写的  ∪  热度 ≥ 0.5
热度 = 每次"被你再次提到"贡献 exp(-Δt/τ),半衰期 14 天
```

**没有任何事件能一直挂载。** 7 天后只有半衰期内被提过的才继续浮着;
超过 14 天没提且热度低于 0.25,正文剥掉沉底 —— 但行和向量留着,
你下次再提,热度回来就又挂上了,只是细节想不起来了。

### 6. 打断与追赶

DSH 关掉期间的时间会被快进。重启后她说得出「你关掉的三个小时里有一顿饭被错过了」——
不是空泛的抱怨,是按延迟算出来的严重程度。

## 二、安装

需要 **DeepSeek Harness** 已经跑起来,并且装了 `dsh-plugin-masterprompt`
(人格来源;没有它插件也能跑,只是没有后台人格可用)。

```bash
# 1. 放到插件的搜索路径下
git clone <this-repo> "%DSH_HOME%/plugins/dsh-plugin-life"

# 2. 装依赖(只有一个 peer)
cd "%DSH_HOME%/plugins/dsh-plugin-life"
npm install

# 3. 重启 DeepSeek Harness
```

`%DSH_HOME%` 默认是 `C:\Users\<你>\.dsh`。
插件的加载靠 `cordis.patch.yml`,它在仓库根目录,不要改名字。

**跨会话记忆使用了embedding模型完成相似任务**(可选,不装也能用,只是没有向量):

> 同一个模型也用来做**活动话题查重**:这次想做的事和最近 7 天做过的事比相似度,
> 太像就换方向。所以装了它有两个好处,不装就两个都没有。

```bash
# 模型:约 91 MB,从 modelscope 下(huggingface 在国内常常连不上)
python -c "from modelscope.hub.snapshot_download import snapshot_download; \
snapshot_download('AI-ModelScope/bge-small-zh-v1.5', cache_dir=r'C:\Users\<你>\.cache\modelscope')"
```

默认会到 `~/.cache/modelscope/AI-ModelScope/bge-small-zh-v1___5` 找模型,
也可以放在 `%DSH_HOME%/dsh-plugin-life/models/bge-small-zh-v1.5`。
找不到模型时插件照常工作,只是判重和"提及检测"退化成纯关键词。

python 解释器默认找 `E:\anaconda\envs\tts0\python.exe`,可以用环境变量 `CAPTAIN_PYTHON` 指定。

## 六、设计逻辑

### 为什么不硬编码

写死的东西不会让她像活的。所以:

- 硬编码的只有**生理学边界**(睡多久、隔多久吃饭、最多清醒多久)
- 边界内的每一个数来自**前几天的条件采样** + 确定性随机(按日期做种子,同一天重跑结果一致)
- 活动内容由 LLM 生成,不是剧本

### 为什么两个 LLM 调用分成两步

| 环节 | 时机 | 人格的作用 |
|---|---|---|
| `composeTask` | 执行**前** | 决定她挑什么、怎么框定。产出必须自包含(执行者是全新会话,没有记忆) |
| `composeFeeling` | 执行**后** | 决定语气和留下的痕迹。吃的是**真实执行结果**,不是预写 |

为什么分开:执行前写的感受是编的;而且两条指令要求相反 —— 任务要"冷",感受要"热"。
混在一起,人格腔调会渗进任务指令,产出"你最近不是想看 X 吗"这种依赖执行者记忆的说法。

### 人格怎么进后台

**后台用的 system prompt 和前台会话里那份是同一份**:包装层 + 人格全文。
不是摘要,不是"你是一个 XX 性格的助手"。

理由见 `prompts/README.md`:一旦两边不是同一份,读数据库里的记录就像在看
**别人照着她的语气写的日记**。

### 为什么记忆是"背景"不是"指令"

挂载的记忆作为 user 角色消息插在你当前这句话**之前**,而且明确写着
「是背景,不是对舰长的指令」和「舰长当前说的话优先于这里的一切;人格优先于记忆」。

不放进 system prompt 的原因:那会让记忆获得比人格更高的稳定性 ——
记忆是会陈旧的,人格不该被一段三周前的经历改写。

### 跨会话记忆为什么先过规则再过向量

- **规则**回答"值不值得当候选":词表加加减减,零成本,可解释,出错能定位到具体哪个词
- **向量**回答"是不是同一件事":这是相似度任务的看家本领,实测同一件事的不同说法
  0.70~0.80,不同的事 0.29~0.55,中间空得很宽
- **热度**回答"以后还会不会被提到":这是时间的活,不是分类的活

三者分工明确。用 LLM 做第一件事会烧钱且不可解释;用规则做第二件事会误判。

### 为什么记忆要压缩成一句话而不是存原话

原话直存等于把"啰嗦"当成"重要"。一段五百字的吐槽和一句"我下周去杭州"占的预算差十倍,
但后者才是要记住的那件。

所以用同一个人格把**整轮对话**(你说 + 她回)压成一句 60 字的第三人称概括。
prompt 里钉了两条:不许照抄原句、超过字数硬砍(不信任模型自己数)。

### 为什么"同一件事"不能用标题判断

早期用的判据是标题的 token 重叠(Jaccard ≥ 0.85)。跑了一周之后实测:

```
33 条事件里,标题最高相似度只有 0.56 —— 阈值 0.85 一次都没命中过
```

因为同一件事的两次记录,标题长得完全不一样:

```
布洛妮娅检索生成式艺术资料并阅读两份创意编程资源页面
布洛妮娅打开 OpenProcessing 的流场作品列表页,抓取作品清单并存成笔记
```

结果 5 天里记了 10 次"生成艺术",每次换个说法。

现在比的是**意图的向量**。实测 17 对真实意图:

```
同一话题   0.616 ~ 0.856
不同话题   0.322 ~ 0.461
```

阈值取 0.62(一开始定的 0.70 漏了一条 0.669 的,而两种错的代价不对等:
误拦只是这一轮不做、45 分钟后再来;漏拦是多一条重复记忆、占几天挂载预算)。

被拦下来之后不是硬跳过,而是**换一个类别重挑一次**,并把这几个相近方向明说给写手
(`{{AVOID}}`)。两次都撞上同一片地才放弃这一轮 —— 不做,比写一条重复的记忆好。

### 为什么压缩看"可压缩内容"而不是文件大小

`life.db` 文件永远比 256 KB 大,这是设计上必然的:

- 永久记忆(keep=1)不参与删减,也就不该占一般事件的预算(这是刻意的决定)
- 文件里还有 SQLite 页开销、索引、空闲页

所以触发口径是"可压缩内容的字节数",而 `status.json` 的 `dbBytes` 把这些数都写出来:

```
fileBytes          磁盘上的文件多大
contentBytes       真正的内容字节(全量,含永久记忆)
compressibleBytes  可压缩的内容字节  ← 压缩看的是这个
limitBytes         上限(默认 200 KB)
usedPercent        到哪了
pages / freePages  总页数 / 空闲页数
```

看到 `fileBytes` 涨而 `compressibleBytes` 没到线,那不是 bug —— 是永久记忆在长。

### 压缩之后文件为什么不会自己变小

这个坑被问过:"life.db 大小没变,不是应该自动压缩了吗?"

压缩确实发生了,只是**文件不会跟着变小**。SQLite 清空数据之后,腾出来的页
进"空闲页列表"留着将来复用,不还给磁盘 —— 这是它的设计,不是故障。

实测那一幕:

```
压缩前  可压缩内容 237.7 KB
压缩后  可压缩内容  40.3 KB      ← 真降了
文件     344 KB → 344 KB         ← 纹丝不动
其中     42 页空闲 = 168 KB(占 48.8%)
```

所以现在压缩之后会顺手 `VACUUM` + `wal_checkpoint(TRUNCATE)`,把空间还回去:

```
344 KB → 104 KB    (26 页,0 空闲)
```

两个细节:
- **WAL 模式下 VACUUM 不够**,结果先落在 `-wal` 文件里,主库要 checkpoint 才真的截短。
  实测同一个库:VACUUM 后 4008 KB 不动,`wal_checkpoint(TRUNCATE)` 后 88 KB。
- VACUUM 会被别的连接挡住(WAL 下有读事务就可能 BUSY),失败不算致命 ——
  压缩本身已经完成,文件不收只是占点磁盘。

判断"压没压"永远看 `compressibleBytes`,不要看文件大小。

## 七、技术实现

### 关键机制

| 机制 | 实现 |
|---|---|
| 心跳 | `ctx.interval`,默认 4 分钟一次 tick |
| 记忆挂载 | `agent/pre-step` 钩子,把 payload 插到最后一条 user 消息之前。**不写入会话历史**,所以不会累积 |
| 回合判定 | `session/event` 的 `turn/end` |
| 状态机推进 | 每个 tick 读 `status.json` 的待办活动,判"该不该、来不来得及、错过了多重" |
| 话题查重 | 意图 → 512 维句向量 → 和最近 7 天的意图比余弦,≥ 0.62 就换方向重挑 |
| 额度熔断 | 识别 429/402/quota/余额错误后关掉所有 LLM 入口,只保留不需要模型的部分 |
| 模型跟随 | 每次调用前重新读主会话的选择,主会话换模型后台最多 2 秒跟上 |

### `node:sqlite` 的两个坑

1. `LENGTH()` 数的是**字符**不是字节。中文一个字 3 字节,直接少算三分之二。
   要用 `length(CAST(x AS BLOB))`。
2. 统计库体积时漏掉最大的字段(`detail`,每个活动 10–11 KB),阈值会形同虚设。
   两个错叠起来,2 MB 的阈值实际对应 11 MB 磁盘、1700 个事件,压缩几乎永远不触发。

### 句向量服务

常驻 python 子进程,模型只加载一次(冷启动约 4 秒),单句约 13 ms。
**两个地方共用同一个进程**:活动话题查重、跨会话记忆的判重与提及检测 ——
起两个进程等于白吃两倍内存。

- **不在插件加载时启动**,推迟到第一次心跳 —— DSH 刚开那几秒不该跟它抢资源,
  但也不能等到第一次活动才起(那样第一次活动正好查不了重)
- 子进程 `unref()`:宿主退出不等它;宿主一退 stdin 断开,python 自己就退了
- 失败、超时、模型缺失 → 返回 null,查重和判重都放行,不影响任何事

### 话题查重怎么和活动流程配合

```
1. 抽类别 → 写手给出 intent
2. 把 intent 转成向量,和最近 7 天的 intent 比
3. ≥ 0.62 就拦下来:
     - 换一个类别,把相近方向作为 {{AVOID}} 明说给写手,重挑一次
     - 第二次还撞 → 这一轮不做,45 分钟后再来
4. 没撞 → 照常执行
```

被拦下来时**不写库**,只在 `status.json` 的 `lastActivity.skipped` 留一条记录:
和哪一条撞了、相似度多少、两次尝试的 intent 分别是什么。

## 八、不做什么

- **不改人格**。`dsh-plugin-masterprompt` 的 `state.json` 只读,一个字节都不动。
- **不硬编码日程**。所有可变的量来自历史 + 随机。
- **不在用户会话里产生回复**。活动不占用任何会话,结果只进数据库。
  只有"值得说的事"才会通过通知进来。
- **不跨库写入**。生活事件进 `life.db`,关于你的事进 `captain.db`,互不读写。
- **不为了"有事做"而做重复的事**。同一片地 7 天内已经走过,就换方向或者这一轮不做。

## 九、已知限制

- DSH 没有浏览器自动化,只有 HTTP。所以「看视频」是抓取视频页的标题/简介/评论,
  「看电影」是抓取影评/剧情 —— 都是真实网络活动,但不是播放。
- 活动 agent 会在 GUI 会话列表里短暂出现再消失(创建后立刻销毁)。DSH 的会话列表没有隐藏开关。
- 跨会话记忆的规则闸门是词表:没见过的表达会漏判。要补就改 `captain_rules.json`。
- 同一件事后来补充的细节不会写进已有那条记忆(那需要再压一次,现在没做)。
- 类别池会被写手不断提出新类别撑大,目前只靠话题查重兜住重复,
  没有做"同义类别合并"(`生成式艺术` / `生成艺术` / `生成艺术史` 现在并存)。
- 挂载记忆有轻微的身份漂移风险。回归测试见 ICR 端点。
