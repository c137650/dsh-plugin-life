# prompts/

这个目录里的文件决定**她说话的样子**。改这里不需要改代码,也不需要重新构建 ——
插件每次调用时都会看一眼文件的修改时间,变了就重新读。

| 文件 | 用在哪里 | 变量 |
|---|---|---|
| `system-wrapper.md` | 所有后台 LLM 调用的 system prompt **包装层**,后面接 masterprompt 的人格全文 | 无 |
| `writer-task.md` | 写手第一步:决定她此刻要去网上做什么 | `{{CLOCK}}` `{{CATEGORY}}` `{{RECENT}}` `{{PROFILE}}` |
| `writer-feeling.md` | 写手第二步:做完之后写摘要、经过、感受,并打两个分 | `{{TASK}}` `{{OUTPUT}}` `{{EVIDENCE}}` `{{PROFILE}}` `{{RECENT}}` |
| `captain-summary.md` | 跨会话记忆:把一轮对话压成一句关于用户的事 | `{{LIMIT}}` `{{CAPTAIN}}` `{{ASSISTANT}}` |

`{{VAR}}` 会被替换成对应内容。写错的占位符会**原样留在文本里**,不会被悄悄替换成空 ——
这样一眼就能看出模板写错了。空值会被替换成空串,那一行随之消失。

## 最重要的一条:后台人格要和前台人格一致

后台那些调用(挑要做什么、写记录、压记忆)用的是**同一个 system prompt**:
`prompts/system-wrapper.md` + `dsh-plugin-masterprompt` 里那份人格的**全文**。

这是有意的设计,不是复用代码的副作用。

一旦两边的人格不是同一份,会立刻出现一种很具体的不对劲:
读数据库里的记录像是在看**别人照着她的语气写的日记**。早期版本就是这样 ——
后台是"手写一段记录指令 + 一份人格摘要",结果人称、锚点、说话习惯全都对不上,
而且摘要里还塞了现成的台词,写出来的东西一眼能看出是拼的。

所以现在的规则是:

1. **不要在后台另写一份人格摘要。** 人格只有一份,在 masterprompt 的模板里。
2. **不要在 `writer-*.md` 里加"你现在是 XX,你的性格是 YY"这种句子。**
   人格由 system prompt 负责,这里的文件只写"这一次要做什么"。
3. 想换后台的人格 —— 换的就是前台的人格,改 masterprompt 的模板即可。
   也可以用 `%DSH_HOME%/dsh-plugin-life/persona.txt` 写一个模板 id 单独指定,
   但那样后台和前台就不是同一个人了,除非你同时把前台也换掉。

换句话说:**后台没有"另一个人格"这个选项**,只有"用哪一版人格"这个选项。

## 为什么任务说明在 user 消息里

system prompt 一行都不动(包装 + 人格全文),所有"这一次要做什么"都放 user。
这样模型看到的 system 和会话里那个她看到的完全一致 —— 只有任务不同。

## 改坏了会怎样

读不到、读出来是空的、文件被删了 —— 都会退回代码里的兜底文本,
插件照常工作,只是提示词变回最简版本。不会因为一个 md 文件写坏了就不加载。
