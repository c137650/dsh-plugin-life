tools: 仓库发布工具（建仓库 / 推新仓库 / 压成一个提交）

给日程插件发布时踩出来的:
- 建仓库的端点是 POST /user/repos。POST /repos/{owner}/{repo} 是「改仓库」，
  对不存在的仓库回 404。
- 空仓库不能让 Git Data API 建 blob（409 Git Repository is empty），
  要用 contents API（PUT /contents/{path}）—— 它能在空仓库上工作，
  第一个 PUT 顺手把分支建出来。
  但 contents API 是一个文件一个 commit，历史会碎成十几次，
  所以仓库非空之后再用 Git Data API 从零建 tree + 根提交，force 挪 ref，压成一个。
- 挪 ref 要 force:true，否则 422 "Update is not a fast forward"
  （根提交不是当前 ref 的后代）。
- github.com:443 时通时不通，api.github.com 稳。所以发布走 API 推送，不走 git 协议。
